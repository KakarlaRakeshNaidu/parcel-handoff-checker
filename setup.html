ThingSpeak cloud alerts

An email when a parcel goes wrong.

Dashboard alerts work while the page is running. ThingSpeak can send an email to your account address even when this dashboard is closed.

What you need

Use the same channel as your ESP32. Enable its seven fields. Keep the Write API Key in the ESP32 sketch, use the Read API Key for this dashboard, and keep the Alerts API Key inside ThingSpeak MATLAB Analysis.

FieldValue
1 · Correct routesCorrect-delivery counter
2 · Wrong trayWrong-delivery counter
3 · UnconfirmedTimeout or ambiguous-delivery counter
4 · Last outcome0 Ready, 1 Correct, 2 Wrong, 3 Unconfirmed
5 · Expected tray0 None, 1 A, 2 B

The current firmware uploads totals and the last result. An increase in Field 2 catches wrong deliveries even when the last result is correct. A batch containing several parcels may only have tray details for its final parcel.

Create the email analysis

  1. Sign in to ThingSpeak. In Account → My Profile, find your Alerts API Key. Check your remaining alert balance.
  2. Go to Apps → MATLAB Analysis → New → Custom. Name it Parcel wrong-tray email.
  3. Download the analysis below and paste it into the MATLAB code editor. Fill in your Read API Key and Alerts API Key inside ThingSpeak.
  4. Save the analysis. Upload one baseline snapshot from the ESP32, then create the rules below. Complete a new wrong-tray test to verify delivery.

The start time prevents old deliveries from producing emails. Generate the file when you are ready to enable monitoring.

Run it automatically in ThingSpeak

  1. Open Apps → React → New React. Choose Numeric, On Data Insertion, your channel, and Field 2 is greater than 0.
  2. Set the action to MATLAB Analysis and select Parcel wrong-tray email. Choose Run action each time the condition is met, then save.
  3. Create Apps → TimeControl → New TimeControl. Run that same analysis every 5 minutes so a temporary network or email-limit failure gets another attempt.

The analysis compares counter increases and uses Alerts history to avoid emailing the same cloud entry again. It reads the last 100 updates. It batches pending wrong counts into one message when needed.

ThingSpeak allows 2 email alerts per 30 minutes, subject to your account balance. Repeated lab tests can reach this limit. Check Alerts history for accepted, sent, or failed status. The script’s display message confirms acceptance; delivery is confirmed in Alerts history.

Check the complete demonstration

  1. Open the dashboard in demo mode. Press Wrong tray. Check the popup and the unread Alerts count. Open Alerts and acknowledge it.
  2. Connect your live channel using its Read API Key. Trigger a wrong delivery on the hardware. Wait for the ESP32 to print ThingSpeak saved entry. The dashboard polls every 15 seconds.
  3. Check the email inbox registered with ThingSpeak, including Spam. You can enable email notifications in your phone’s mail app.
  4. Close the dashboard and repeat a hardware test. The cloud email rule should still run within the service’s limits.

Desktop notifications are optional. Enable them in the dashboard’s Alerts panel and allow your browser’s permission prompt. They need HTTPS or localhost, browser support, and this page to keep running. Browser background throttling can delay them.

Hardware timing stays the same. The ESP32 uploads between handoffs, at least 20 seconds apart. This dashboard displays the latest completed result, not live IR sensor states. The counters restart when the ESP32 resets.
